# agentic_dev_env

A minimal [Copier](https://copier.readthedocs.io) template for agentic engineering with
[Claude Code](https://code.claude.com). It gives every new project three things:

1. **`eng-wiki/`** — the project's engineering memory: status/handover, decisions (ADRs),
   learnings, version-pinned stack docs. Small, linked, one fact per page.
2. **Six skills** that take a project from idea to a tailored scaffold and keep the wiki alive:
   `spec` · `architect` · `stack-docs` · `tailor` · `wiki` · `evolve`.
3. **A barebone hook set**: secret and destructive-command guards organised in protection
   classes (P0 lock … P4 audit), plus wiki hooks that inject status and nudge recording.

It deliberately ships little. Project-specific pieces (scaffold, commands, extra skills, extra
hook rules) are generated by `tailor` when a project needs them.

## Use

```bash
uvx copier copy --trust gh:FRST-FRYTL/agentic_dev_env my-project
cd my-project && claude
# then: /spec <what you want to build>  →  /architect  →  /stack-docs  →  /tailor init
```

Update a project to a newer template version: `uvx copier update --trust`. `CLAUDE.md`,
`eng-wiki/` content and `specs/` belong to the project and are never overwritten.

`--trust` is needed for the post-copy tasks (`git init` and an initial commit).

## Layout of a generated project

```text
CLAUDE.md               ~40 lines: start here, commands, workflow, memory rule, stack-docs index
specs/                  one spec per feature (requirements · scope · verify · tasks)
eng-wiki/               index.md · log.md · status.md · decisions/ · stack/
.claude/settings.json   hook registration + permission deny rules for credential files
.claude/hooks/          stdlib Python hooks + tests (see .claude/hooks/README.md)
.claude/skills/         spec · architect · wiki · stack-docs · tailor · evolve
.pre-commit-config.yaml gitleaks for your own commits
```

## Hooks at a glance

| Class | Decision | Examples |
|---|---|---|
| P0 Lock | deny, fails closed, no switch | reading `.env`/keys/`~/.ssh`; editing hooks or settings |
| P1 Block | deny | secret in prompt or staged commit; `curl \| sh`; force-push; `reset --hard` |
| P2 Confirm | ask (block when autonomous) | push to main; `--no-verify` |
| P3 Advise | note to Claude | wiki page checks; "record this decision?" after a commit |
| P4 Audit | log | settings changed mid-session |

Hooks are tripwires, not a sandbox. For unattended runs use the strict sandbox profile
(`claude --settings .claude/sandbox-autonomous.json`).

## Evolution mode (optional)

A separate, user-level repo (`dev-env-evolution`) collects signals from every project's hooks
(false positives, hook errors, ignored nudges, generated skills). The `evolve` skill turns them
into improvement candidates and promotes accepted ones into this template. Turn it on with
`/evolve setup` in any generated project.
